# Where this engine differs from the Blueprint

`apps/api` and `packages/shared` were delivered from the Blueprint (`nadeemmurtaza/erp-1`) by `scripts/sync-client.mjs`, then adapted for ROYA. A later upgrade sync **overwrites engine files**, so every edit below is a place a sync can silently undo ROYA's behaviour. Each has a test that fails if it is lost; the right long-term answer for each marked **upstream** is to land it in the Blueprint so the fork disappears.

## Blueprint modules ROYA does not ship

Not copied, on purpose, because a couture atelier with one location does not use them: `reviews`, `loyalty`, `wallet`, `recommendations`, `onsitemessages` (storefront features, tied to the Pakistani market or to a retail floor), `pos`, `transfers`, `tradingpartners` (a second location and trading partners), `hr`, `payroll`, `attendance`, `orgstructure`, `tasks` (a workforce ROYA does not run in this system), `settlements`, `bankfacilities`, `accounts`, `marketplace`, `managed-services`, `identity-verification`, `rag`. `accounting` is shipped but **off**: switching it on starts an immutable general ledger, which is the owner's decision (see [OPEN-QUESTIONS](OPEN-QUESTIONS.md) 4). Each is a copy of its directory plus a registry entry, so adding one later is cheap.

## The back office (`apps/admin`)

A copy of the Blueprint's `/admin` tree (`apps/web`), pruned to the modules above and adapted. It is a separate Next.js app (port 3002, English only) that reaches the API through its own `/api/v1` rewrite. Adaptations, so a later sync of the Blueprint's admin is a merge and not an overwrite:

- Brand, not literals: Tailwind's font stacks and the 404 page read `@newax/shared`; the second language's name and the currency labels come from `SECOND_LOCALE` and `CURRENCY`. The wire fields keep the Blueprint's `…Ur` names (`nameUr`, `labelUr`) but hold Arabic.
- Pages and nav entries for modules ROYA does not ship are gone, and `nav-registry.spec.ts` fails if a nav entry points at a page that does not exist. The launchpad spec lists the same entries as `NOT_SHIPPED`. Profit & loss, cash flow and fiscal periods are views over the ledger, so they follow the `accounting` module (the Blueprint tagged them `finance`) and say so when it is off.
- Three dropdown loads asked for `pageSize=200`; the API caps a page at 100, so they failed. They now ask for 100 (the Blueprint has the same bug: **upstream**).
- It looks like the storefront: the same parchment and ink (pearl on dark), square corners, Jost for body, Cormorant Garamond for titles and figures, Cinzel for the name, tracked capitals for labels and buttons, and it opens dark like the shop. All of it is read from `BRAND.storefront` (row 19); the fonts are the same `@fontsource` packages the storefront self-hosts. Feedback greens and reds, the rating star and the other chart hues stay the Blueprint's, because they mean the same thing in every brand.
- "View store" goes to `NEXT_PUBLIC_SITE_URL`, not the relative `/en`.
- Sessions are held in the browser's storage (the Blueprint's design). The API checks every permission on every call, so a forged local session reads nothing; moving the token to an httpOnly cookie is a follow-up.
- `paisa` metric unit names are kept so the API's metrics keep their identity.

The desk (`apps/storefront`, bilingual) is the daily console for orders, payments and requests; the back office is for the catalogue, stock, suppliers, production and finance.

## Leftovers known and not fixed

- The gateway paths in `payments.service.ts` (`handleCallback`, `redeemGiftCardCode`) also move an order to CONFIRMED without a status event, and without checking that it is still PENDING. ROYA enables no gateway (bank transfer only), so neither is reachable; fix both upstream before adding a card provider.
- CSV import columns are still named `price_pkr`; loyalty tiers (their spend thresholds were set for PKR) belong to a module ROYA does not ship; some `shared` garment defaults are Pakistani garments (ROYA seeds its own gown). None is reachable from the storefront.
- The legacy cookie/refresh-cookie names (`LEGACY_*`) are kept so a session survives a rename.

## Defects found in the extractor (`scripts/sync-client.mjs` in the Blueprint)

Fixed here by hand; worth fixing at the source so the next client does not repeat them: the migration purge loses triggers and extensions the later migrations depend on; spec files that import a module the client does not ship break `tsc`; it ships no app scaffold (`main.ts`, `app.module.ts`, `package.json`, `eslint` config); the generated `.env` has no `MODULES`; it ships region-specific payment providers and seed data.
